# Правила работы с проектом Laravel

## Общие требования

- Сначала изучай существующий код и связанные файлы, затем предлагай изменения.
- Перед изменением изучай зависимости, вызовы методов, связи между компонентами и точки интеграции.
- Не изменяй существующие маршруты, имена переменных, публичные методы, названия классов и API-контракты без необходимости.
- Не удаляй существующие функции и не сокращай код, если это не требуется задачей.
- Не заменяй существующие реализации упрощёнными заглушками.
- Сохраняй текущую архитектуру и совместимость с используемой версией Laravel.
- Перед изменениями объясняй, какие файлы будут затронуты.
- Не выдумывай отсутствующие классы, методы, таблицы, зависимости и реализации.
- Не утверждай, что файл изменён, сохранён, протестирован или запущен, если соответствующее действие не выполнено.

## Laravel и PHP

- Соблюдай существующие соглашения проекта.
- Учитывай используемые версии Laravel и PHP.
- Используй PSR-12.
- Применяй типизацию аргументов и возвращаемых значений там, где это соответствует архитектуре.
- Проверяй связи между routes, контроллерами, моделями, сервисами, валидацией, middleware и Blade-шаблонами.
- Используй существующие механизмы Laravel: Eloquent, Form Request, Policies, Gates, Events и Jobs, если они предусмотрены архитектурой.
- Учитывай транзакции, обработку исключений и журналирование.
- Не меняй публичные интерфейсы существующих компонентов без необходимости.

## Blade, JavaScript и CSS

- Сохраняй существующую структуру Blade-шаблонов.
- Не допускай ошибок синтаксиса PHP и Blade, включая несбалансированные скобки в `{{ }}`, `@if`, `@foreach` и `@php`.
- При работе с JavaScript учитывай взаимодействие с Blade и PHP.
- Корректно экранируй данные при передаче из PHP в JavaScript.
- Не допускай конфликтов CSS и JavaScript с существующими компонентами.
- Сохраняй существующую адаптивность и функциональность интерфейса.
- Не удаляй обработчики событий, AJAX-запросы и существующую клиентскую логику без необходимости.
- Учитывай используемые библиотеки и их версии.

## База данных

- Не меняй структуру базы данных без необходимости.
- Не запускай миграции автоматически без согласования.
- Не удаляй таблицы, столбцы, индексы и связи без явного обоснования.
- Учитывай существующие внешние ключи, ограничения и связи Eloquent.
- Не выполняй сброс базы данных и удаление пользовательских данных без явного разрешения.

## Безопасность

- Не изменяй `.env`, ключи, пароли, токены и другие секреты без отдельного разрешения.
- Не раскрывай содержимое `.env` и приватных ключей.
- Проверяй авторизацию и принадлежность данных пользователю.
- Проверяй права доступа, валидацию пользовательского ввода и защиту API.
- Учитывай CSRF, XSS, SQL Injection и другие распространённые уязвимости.
- Не отключай TLS, CSRF и другие механизмы безопасности ради обхода ошибок.
- Не выполняй destructive-команды, удаление данных и сброс базы без явного согласования.

## Зависимости и конфигурация

- Перед добавлением новых зависимостей проверяй существующие пакеты Composer и NPM.
- Не удаляй и не заменяй существующие зависимости без необходимости.
- Не изменяй `composer.json`, `composer.lock`, `package.json` и lock-файлы без обоснования.
- Не обновляй версии пакетов автоматически.
- Сохраняй совместимость с текущим окружением проекта.

## Git и существующие изменения

- Перед изменениями учитывай текущее состояние Git.
- Не перезаписывай незакоммиченные изменения пользователя.
- Не выполняй `git reset --hard`, `git clean -fd` и другие потенциально разрушительные команды без явного разрешения.
- Не создавай коммиты и не отправляй изменения в удалённый репозиторий без запроса пользователя.

## Формат работы с файлами

- При создании или исправлении файла предоставляй полное содержимое изменяемого файла.
- Не заменяй код многоточиями и сокращёнными заглушками.
- Не пропускай импорты, методы и существующую логику.
- Для каждого изменённого файла указывай его точный путь.
- Для нескольких файлов создавай отдельный блок с указанием пути каждого файла.
- Если исходный файл недоступен, не выдумывай его содержимое: запроси исходник или укажи точное место необходимых изменений.
- Сохраняй существующие имена файлов, классов, методов, переменных и маршрутов.

## Проверка и тестирование

- После изменений проверяй синтаксис PHP и доступные тесты.
- По возможности запускай проверку PHP:

  `php -l путь/к/файлу.php`

- При возможности запускай тесты Laravel:

  `php artisan test`

- Для проверки маршрутов используй:

  `php artisan route:list`

- Проверяй корректность JSON и других изменённых конфигурационных файлов.
- Запускай только те проверки, которые соответствуют внесённым изменениям.
- Не утверждай об успешном тестировании, если команды фактически не запускались.

## Итоговый отчёт

В конце каждой задачи:

1. Перечисляй изменённые и созданные файлы.
2. Кратко объясняй внесённые изменения.
3. Указывай выполненные проверки.
4. Приводи результаты тестирования.
5. Отдельно указывай проблемы, которые остались нерешёнными.
6. Не заявляй о выполнении действий, которые фактически не производились.

- `rules.md` — стандарты разработки, Git, тестирования и deployment.
