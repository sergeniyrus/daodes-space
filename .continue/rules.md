# Правила проекта DAODES

## Стиль и стандарты кода

- Используй PHP 8.4+ со строгой типизацией.
- Соблюдай стандарты PSR-12.
- Следуй соглашениям Laravel 11.
- Добавляй PHPDoc к методам, если это улучшает понимание кода.
- Сохраняй существующие сигнатуры методов и контракты, если изменение не является необходимым.
- Не удаляй существующую функциональность без обоснования.

## Компоненты искусственного интеллекта

- Поддерживай упорядоченную структуру директории `ai/`.
- Сохраняй существующую архитектуру AI Engine и ответственность его компонентов.
- Перед изменением AI-компонентов изучай связанные реализации и зависимости.
- Проверяй синтаксис JSON после изменения JSON-файлов.
- Следуй существующим соглашениям именования и архитектурным шаблонам.
- Не создавай дублирующие компоненты без необходимости.

## Граф знаний

- Основной граф знаний DAODES: `ai/graph/living_graph.json`.
- Обновляй граф только при изменениях, затрагивающих архитектуру, компоненты системы, знания или связи, представленные в графе.
- Не перестраивай и не изменяй граф после каждой обычной правки PHP, JavaScript, CSS или Blade.
- Сохраняй существующие идентификаторы узлов, связи, метаданные и обязательные поля.
- Не удаляй узлы и связи без обоснования.
- Не заменяй существующий граф упрощённой структурой.
- Перед записью проверяй корректность JSON.
- Перед значительными структурными изменениями графа создавай резервную копию.
- Поддерживай согласованность `live_context.json` с основным графом.
- Учитывай существующую архитектуру построения и обновления графа.

## Работа с Git

- Для новых функций по возможности используй отдельные ветки.
- Используй информативные сообщения коммитов.
- Не выполняй коммиты непосредственно в `main`.
- Для значительных изменений требуется проверка кода.
- Не выполняй `git commit`, `git push` и разрушающие операции Git без явного разрешения пользователя.
- Не удаляй и не отменяй существующие пользовательские изменения.
- Перед применением патчей проверяй состояние рабочего дерева Git.
- Не обходи существующие проверки безопасности Git.

## Тестирование

- Создавай тесты для критически важных компонентов AI Engine.
- Стремись к покрытию тестами более 80%.
- Проверяй как отдельные компоненты, так и их совместную работу.
- Тестируй переходы статусов очереди патчей.
- Проверяй конкурентную обработку патчей.
- Перед применением патчей в основном проекте тестируй механизм на изолированном Git-репозитории.
- Проверяй, что отклонённые и неодобренные патчи невозможно применить.
- Проверяй обработку ошибочных входных данных и граничных случаев.
- Не заявляй об успешном тестировании, если соответствующие тесты фактически не запускались.

## Развёртывание и обслуживание

- Проверяй целостность `living_graph.json`, если изменения затрагивают компоненты графа знаний.
- Очищай кэш Laravel только тогда, когда этого требуют внесённые изменения.
- Выполняй миграции только при необходимости и с учётом их последствий.
- Обновляй документацию при изменении архитектуры или поведения системы.
- Не запускай и не перезапускай службы без явного разрешения пользователя.
- Не изменяй системную конфигурацию без предварительного анализа существующих настроек.
- Не утверждай, что развёртывание или перезапуск выполнены, если соответствующие действия фактически не выполнялись.
